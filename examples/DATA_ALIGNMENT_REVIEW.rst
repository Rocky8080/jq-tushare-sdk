结论
----

当前程序适合作为固定样本、日线数据值的基础对账器，不能验证所有平台差异。
已有分片与摘要保护不等于运行区间完整、来源可追溯或接口业务语义完整。
原生产策略的七种命名数据 API 都出现在样例中，但原策略有 57 处调用，
多种参数、查询过滤与排序、回看长度、选股逻辑没有被当前样例复现。
财报/预告支持、PIT、实时分钟、成交、分红及收益仍不能从该样例取得认证。

已核实的问题
------------

1. P1：整组快照遗漏无法靠比较器可靠识别。
   比较器只查看两个输入实际存在的配对键，没有外部预期日期/阶段清单。
   从真实四组日志删去第一整组之后，read_log 返回三组且没有完整性问题，
   单端报告仍为 awaiting_joinquant_log。若两端同样漏掉一组，也没有配对键
   可指示遗漏。单个分片缺失能被识别；本地采集器另有预期数量检查，
   但数量检查不能替代对每个预期日期和阶段的验证。
   建议：用冻结的对账协议显式列出预期交易日、阶段、case_id 和执行结果。

2. P1：财务语义和重要来源诊断尚未覆盖。
   财报仅查询最近三个完成季度的两个金额字段，没有前一年同季、年度累计、
   四季滚动 TTM、收入/利润同比、修订及公布前后边界、跨表交集、过滤排序探针。
   原生产策略依赖其中的财报回退、同比与估值条件。
   真实估值返回含 fundamentals_audit / valuation_provenance；当前 _frame 不保存
   这些属性。PE/PB 来源、逐股 snapshot_date、stale/missing 状态和 as_of 因而丢失。
   示例只保存通用 data_contract，不能据此诊断某个值的出处或证明历史 PIT。

3. P1：此前长假问题不会被当前正常窗口探针复现。
   样例只查询 count=21；原策略 calculate_3day_industry_relative 使用固定自然日窗口。
   本次真实缓存再次核实：2026-05-07 回调的 05-01 至 05-06 只有一根指数线，
   2026-05-08 回调的 05-02 至 05-07 只有两根；count=3 两次都取得三根。
   缺口来自窗口规则，不能简单归因于源行情缺失。
   建议：增加相同截止日的 start/end 与 count 对照及原策略默认值触发记录。

4. P2：接口失败时，部分请求参数不能忠实还原。
   requests 只登记了价格、估值、财报和预告；calendar、universe、industry、
   index membership、current quotes、启用的 minute 请求失败时使用通用回退。
   收盘后 industry 实际查 previous_date，回退却只写 data_date=today；
   指数成分失败时也丢失 index 和正确的查询日期。
   error 文本截断到 600 字，没有 traceback、调用起止时间与耗时。
   建议：每个 case 在调用前记录完整 API、参数、字段、filter/order/limit 和 cutoff，
   失败保留同一请求对象及异常链，别用默认股票名单替代实际请求。

5. P2：返回结构和规范化细节不足。
   _frame 只保留指定字段，排序列和记录，转换缺值/非有限值为 None；
   未保存原始行序、索引类型、dtype、全部返回字段及缺值原始类型。
   compare_section 对照 params/keys/units 和规范化行，却不比较 columns/schema。
   当前只有 list get_price，没有单股形态、history、attribute_history 或字典结果对照。
   建议：同时保留 typed raw response 和 normalized response，结构差异单独报告。

6. P2：日志证据还不能形成独立、完整的运行证据包。
   本地 protocol.json 保存源码/SDK/缓存摘要；聚宽快照只带 VERSION 和 config 摘要。
   相同版本字符串和配置不能证明函数体相同；来源标签也不是平台真实性认证。
   策略日志无运行类型、运行起止范围和运行 ID；快照 ID 无法替代原生任务身份。
   comparison.json 仅保存摘要和差异；成功字段和错误接口的完整原始 payload 不在其中。
   建议：导出任务信息、两边实际源码、协议、原始日志、解码 JSONL 和差异 JSON/CSV，
   用 manifest 与输入文件 SHA256 关联；区分已执行、未覆盖、不支持、缺数据与失败。

覆盖清单
--------

下面的“有观测”只表示程序采集了该信息，尚无聚宽实际日志可以比较。

* 日线 OHLCV/成交额、三个指数日线：有观测；股票只含六只固定样本。
* 前复权/不复权：有请求；本地不复权返回不支持，后复权和除权事件未覆盖。
* 长假/周末交易日：有基础日历；自然日窗口、周/月调度未覆盖。
* 查询截止日与上一交易日：有记录；未来 EOD 拒绝、无日期默认值及自然日期对象未覆盖。
* 旧行情/日期错位：预期日线行与日历可以提示样本缺口；逐字段实际来源日期记录不足。
* 自动补齐、权限、限频与等待恢复：只读探针不验收补数或实时平台的状态流转。
* 股票代码、上市退市：代码集有数量和摘要；全表默认不导出，302/920/退市边界无样本。
* 行业 L1/L2：有观测；L3、行业指数、历史调整日、provider/compat 来源未覆盖。
* 指数成分：三个日期敏感查询有观测；权重、来源快照日期和调整日前后未覆盖。
* PE/PB/市值：六样本有观测；负/零/缺失 PE、过期估值及有符号 TTM 未覆盖。
* 财报 date/statDate：有请求；date 模式现有异常及季度覆盖不足已记录。
* 财报单季/累计/同比/TTM/PIT：覆盖不足，没有语义及边界用例。
* 业绩预告：只探测 code/pub_date；数值、文本、窗口空日认证与研究接口未覆盖。
* ST/停牌：有当前布尔值；历史变更样本、skip/fill 停牌选项未覆盖。
* 涨跌停价、开盘价、last_price：仅作环境参考，比较器不认证这些值。
* 分钟与时点可见性：默认禁用；启用后也只请求两个五分钟窗口，无全日完整性认证。
* ETF、北交所、行业指数等数据路由：没有相应默认样本。
* 查询 filter/order/limit、跨表交集、空结果结构：未覆盖。
* 原策略筛选阶段、因子、候选池及最终排名：没有复现，仅有样本 MA20/5 期收益。
* 科创板股数、T+1、滑点/费率、限价/拒单：不下单，不能验证。
* 分红、送转、登记日权益、FIFO 税：不持仓，不能验证。
* 资金/持仓/NAV/收益曲线：没有双端交易证据，不能验证。
* 实时调度、任务 snapshot/恢复、g 状态、Redis、邮件：不属于该数据探针的验收范围。

供后续 Codex 使用的日志要求
-------------------------

最少包含 run_id、平台任务身份/运行模式、程序源码、源码校验值、SDK 版本、
配置与预期日期/阶段/case 清单、实际 callback/data/cutoff 时间、API 与完整参数、

带原始日志 SHA256、snapshot_id、日期/阶段、section 摘要及完整 payload。

# SDK 透明回测性能优化设计

## 目标

在不修改聚宽策略源码、不跳过任何策略回调、不改变数据时点和交易语义的前提下，提高本地回测运行效率。优化必须对策略透明，并保证同一策略、同一缓存数据和同一回测参数产生相同的订单、成交、目标持仓信号和每日收益。

## 基线

基线回测：

- 运行 ID：`20260711-023240_20260711-023226_d0fa29e1_small_cap_gem_star_merged_strategy_pro_live_20260602_20260702`
- 策略版本：`5.9.0`
- SDK 版本：`0.10.17`
- 回测区间：`2026-06-02` 至 `2026-07-02`
- 总耗时：`467.981801` 秒
- 策略回调耗时：`466.631528` 秒
- `daily` 后端读取：196 次，`78.096921` 秒
- `adj_factor` 后端读取：367 次，`8.834438` 秒

当前缓存已经减少了 SQLite 查询次数，但仍按精确日期区间和 `count` 保存大量相互重叠的全市场 DataFrame。策略级逐股 `get_price` 调用还会重复执行切片、复制、复权合并和输出格式转换，这些耗时被归入策略回调，没有出现在后端接口耗时中。

## 约束

- 聚宽策略文件内容和哈希保持不变。
- 保持 `get_price`、`history`、`attribute_history` 的现有返回格式和异常行为。
- 保持开盘时只允许读取前一交易日数据的防未来数据约束。
- 保持 `fq="pre"` 的前复权语义；复权基准必须使用本次查询截止日对应的最新因子。
- 返回独立的 Pandas DataFrame，策略修改返回值时不得污染缓存。
- 不改变调度顺序、持仓修复、止盈止损、下单和估值逻辑。
- 不新增模拟数据或模拟测试，遵循工作区 `AGENTS.md`；使用现有测试和真实缓存回测验证。

## 方案选择

采用“统一行情主缓存 + SQLite 读取优化”的组合方案。第一阶段不替换 Pandas/SQLite，也不尝试自动改写策略循环，以控制兼容风险。

未选择的方案：

- DuckDB、Polars 或 Arrow 数据引擎：潜在性能更高，但返回顺序、类型和空值语义的兼容验证范围过大，留作后续阶段。
- AST 自动批量化策略循环：难以保证任意聚宽策略的副作用和异常顺序，不能满足结果完全一致要求。
- 跳过重复调仓或持仓修复：会直接改变交易行为，不属于透明优化。

## 架构

### 统一行情主缓存

`DataPortal` 在 `optimize_data=True` 时维护每个行情 API 的单份规范化主缓存。缓存覆盖回测开始日前所需的最大回看区间至回测结束日，并按 `ts_code` 和 `trade_date` 排序。

主缓存按需加载：第一次访问 `daily`、`adj_factor`、`fund_daily`、`fund_adj` 或 `index_daily` 时才读取对应数据。不同的 `start_date`、`end_date` 和 `count` 请求共享同一份底层数据，不再为每个窗口保存完整副本。

如果策略使用动态表达式导致静态分析无法覆盖实际回看起点，`DataPortal` 必须在收到超出主缓存下界的请求时向前扩展缓存并去重合并。不得因为预估区间不足而缩短返回序列；扩展失败时按原查询路径读取该请求。

回测引擎把以下只读边界传给 `DataPortal`：

- 回测开始日期；
- 回测结束日期；
- 从策略静态分析得到的最大价格回看起点；
- 当前回调允许访问的数据截止日期。

主缓存可以包含未来回测日的数据，但所有公开 API 必须先应用当前上下文的数据截止日期，再执行切片。未来数据不得出现在返回结果、`count` 计算或复权基准中。

### 按股票索引

主缓存加载后建立 `ts_code -> 行号或分组 DataFrame` 索引。小批量和单只股票查询直接从索引读取；大批量查询使用主缓存上的向量化代码过滤。索引只引用主缓存，不复制完整行情。

范围请求按以下顺序处理：

1. 规范化证券代码和字段。
2. 将请求截止日限制到当前上下文允许的数据日期。
3. 从股票索引获取候选数据。
4. 应用 `start_date`/`end_date` 或每只股票的 `count` 截断。
5. 应用复权。
6. 转换为 JoinQuant 字段和日期格式。
7. 返回独立副本。

### 前复权缓存

原始行情和复权因子分别保存在规范化主缓存中。对于 `fq="pre"` 请求，按股票和查询截止日期计算复权比例：

`row_adjusted_price = row_raw_price * row_adj_factor / end_date_latest_adj_factor`

SDK 缓存“股票 + 行情 API + 查询截止日期”对应的已复权规范数据，再对不同起点、`count` 和字段请求做切片。缓存键不包含字段列表，避免同一股票、同一截止日期因字段组合不同重复复权。

已复权缓存必须有容量上限并使用 LRU 淘汰，防止长区间、多策略回测无限增长。缓存项不得包含查询截止日之后的数据。

### SQLite 读取

为高频行情表增加适合全市场日期区间读取的复合索引：

- `daily_quote(trade_date, ts_code)`
- `adj_factor(trade_date, ts_code)`
- `fund_daily_quote(trade_date, ts_code)`
- `fund_adj_factor(trade_date, ts_code)`
- `index_daily(trade_date, ts_code)`

回测读取使用生命周期受控的持久连接，启用只读友好的 `query_only`、`temp_store=MEMORY`、合理的负值 `cache_size` 和 `mmap_size`。数据更新仍使用独立写连接，避免读写连接状态相互污染。

### 兼容回退

现有精确窗口缓存路径保留为兼容实现：

- `optimize_data=True` 使用统一行情主缓存。
- `optimize_data=False` 使用当前直接查询路径。
- 主缓存加载遇到内存不足、模式不匹配或缺失必要字段时，记录一次明确警告并回退到当前查询路径。
- 回退不得吞掉原有的缺失数据和不支持字段异常。

## 性能统计

性能报告把策略调用与后端读取分开统计：

- 聚宽公开数据 API 调用次数和耗时；
- 最终结果缓存命中/未命中；
- 主缓存命中/加载次数、加载行数和耗时；
- SQLite 后端调用次数和耗时；
- 股票切片、前复权、格式转换耗时；
- 主缓存和复权 LRU 的峰值项目数。

原有报告字段保持不变，新统计作为附加字段写入 `performance_profile`，旧报告读取逻辑继续可用。

## 错误处理与安全

- 主缓存中的日期或代码列不符合要求时，错误信息必须包含 API 名称和缺失字段。
- 数据截止日期晚于当前上下文时必须主动截断，不依赖调用方正确传参。
- 缓存返回值始终复制，防止策略对 DataFrame 的原地修改影响后续调用。
- 日志不得输出 Redis 密码、Tushare Token 或其他认证字段；配置对象只记录脱敏状态。

## 验证

### 行为一致性

使用当前 5.9.0 策略快照、真实 SQLite 缓存和完全相同参数重新运行完整回测。比较：

- `trades/transactions.csv`：逐行逐字段一致；
- `trades/orders.csv`：逐行逐字段一致；
- `signals/target_portfolio_signals.jsonl`：忽略运行目录信息后逐条一致；
- `reports/performance.csv`：逐行逐字段一致；
- `reports/summary.json`：排除 `performance_profile` 后一致；
- 策略日志中的选股、风控和下单结果一致。

订单委托 ID 如由运行时随机生成，则在比较时只排除该运行标识字段，证券、方向、数量、价格、费用、时间和状态必须一致。

### 回归验证

- 运行仓库现有完整测试集。
- 运行 `git diff --check`。
- 使用真实缓存执行单只、小批量、1,500 只股票的 `get_price` 只读微基准。
- 对有无 `optimize_data` 的结果进行语义对比。
- 检查回测进程峰值内存，确认统一主缓存没有高于当前重叠窗口缓存的峰值。

### 性能门槛

- 基线总耗时：`467.981801` 秒。
- 第一阶段验收：总耗时不超过 `328` 秒，至少提升 30%。
- `daily` 和 `adj_factor` 后端读取次数分别降低到不超过 5 次。
- 若行为一致但未达到性能门槛，保留结果并继续分析主缓存切片和复权转换耗时，不以改变策略语义换取达标。

## 交付范围

- `DataPortal` 统一行情主缓存和按股票索引。
- 前复权规范数据 LRU。
- SQLite 复合索引和只读连接配置。
- 回测引擎向数据层传递只读日期边界。
- 分层性能统计及报告展示。
- Redis 配置日志脱敏。
- 版本号、变更日志和 README 中的版本同步。

不包含策略源码修改、策略参数调整、调度优化、候补池缩减或自动批量改写。
